# 5분 데모 시나리오

면접·시연용 스크립트. 사전 준비: `docker compose up --build` 후
`docker compose exec api python -m app.seed --demo` 실행, http://localhost:3000 접속.

계정(비밀번호 공통 `demo1234!`): `researcher@demo.kr` / `manager@demo.kr` / `admin@demo.kr`

## 0:00 — 문제 한 줄 (말로)

> "국가 R&D 연구비는 규정 위반 시 환수·제재로 이어지는데, 제출 전 검증이 전부 엑셀 수작업입니다.
> 그 검증을 AI+룰 엔진이 먼저 하고 사람이 결정만 하게 만든 시스템입니다."

## 0:30 — 연구원: 집행 등록 → 제출

증빙은 `docs/samples/card-receipt.png`(가상의 신용카드 매출전표)을 쓴다.
아래 값은 **전표에 적힌 내용과 일부러 정확히 일치**시킨 것이다 — 대사 룰이 모두 통과하는
기준선을 먼저 보여주고, 그다음 값 하나만 틀리게 바꿔 룰이 잡아내는 걸 보여주는 순서가 좋다.

1. `researcher@demo.kr` / `demo1234!` 로그인 → 집행 건 → **집행 등록**
2. 다음 값을 그대로 입력한다:

   | 항목 | 값 |
   |---|---|
   | 과제 | `P-2026-001 자율 지게차 인지 모듈 고도화` |
   | 비목 | `연구재료비` |
   | 제목 | `실험용 시약 및 소모품 구입` |
   | 사용 용도 | `인지 모듈 성능시험용 시약 (연구 수행에 직접 사용)` |
   | 거래처명 | `(주)한빛사이언스` |
   | 사업자등록번호 | `101-81-16293` (하이픈은 서버가 자동 제거한다) |
   | 금액 | `1320000` (부가세 포함 합계) |
   | 집행일 | `2026-08-20` |
   | 증빙 파일 | `docs/samples/card-receipt.png` |

3. "등록하고 제출" → 상세 화면: "자동 검증 파이프라인 실행 중" 배너

### 값 하나만 바꿔 룰을 깨뜨리는 법

기준선을 보여준 뒤, 새 건을 하나 더 등록하면서 아래 중 하나만 바꾼다.
증빙 파일은 그대로 두는 게 핵심이다 — **입력값과 증빙이 어긋나는 상황**이 실제 정산에서
가장 흔한 지적 사유이고, 그걸 시스템이 잡는 장면이 이 데모의 핵심이다.

| 바꿀 값 | 걸리는 룰 | 결과 |
|---|---|---|
| 금액을 `1200000`(공급가액만)으로 | R-EVD-002 | 위반 — 증빙 합계와 불일치 |
| 집행일을 `2026-08-19`로 | R-EVD-003 | 주의 — 증빙 발행일과 불일치 |
| 사업자번호를 `1234567891`로 | R-EVD-004 | 위반 — 증빙의 번호와 다름 |
| 사업자번호를 `1234567890`으로 | R-VND-001 | 위반 — 체크섬 불일치(오타) |
| 사업자번호를 비워두면 | R-VND-001 | 주의 — 미입력 |
| 집행일을 `2026-08-23`(일요일)로 | R-DAY-001 | 주의 — 휴일 집행 |
| 집행일을 `2025-12-22`(협약 전)로 | R-PRD-001 | 위반 — 연구기간 외 |
| 비목을 `연구시설·장비비`로 | R-CAT-001 | 주의 — AI 제안 비목과 불일치 |
| 비목을 `간접비`, 금액을 `20000000`으로 | R-BGT-001 | 위반 — 예산(1,500만) 초과 |
| 증빙을 첨부하지 않으면 | R-EVD-001 | 위반 — 증빙 누락 |
| 시드 데모와 같은 값으로<br>(사업자번호 `1234567891` / `480000` / `2026-02-10`) | R-DUP-001 | 주의 — 중복 의심 |

중복 판정은 거래처 **이름이 아니라 사업자등록번호**로 한다(같은 업체를 다르게 적어도 잡힌다).
마지막 행은 증빙과 값이 전부 어긋나므로 R-EVD-002·003·004도 함께 뜨는데, 의도된 결과다.

`NTS_API_KEY`가 없으면 R-VND-003(사업자 상태 미확인)이 항상 주의로 뜬다 — 정상이다.
외부 API가 없어도 워크플로가 멈추지 않는다는 걸 보여주는 부분이니 그대로 설명하면 된다.

## 1:30 — 자동 파이프라인 (기다리는 동안 설명)

> "제출과 동시에 DB 큐에 작업이 들어가고 워커가 SKIP LOCKED로 집어갑니다.
> AI가 증빙에서 거래처·금액·사업자번호를 추출하고, 15개 룰이 대사·기간·예산·휴폐업을
> 검사합니다. AI가 죽어도 룰 검증만으로 계속 가고, 수기 대조 플래그가 남습니다."

수 초 후 화면이 자동 갱신되어 **검토 대기** + 검증 결과 목록이 나타난다.

- 보여줄 것: 3단 대조(입력값 ↔ AI 추출값), 위반/주의 배지, 룰 코드별 근거 데이터

## 2:30 — 담당자: 검토 → 승인

1. 로그아웃 → `manager@demo.kr` 로그인 → 알림 벨(검토 대기 알림) → 해당 건
2. FAIL이 있는 건이면 **승인이 막히고 override+사유**를 요구하는 것을 보여준다
   - 포인트: "차단이 아니라 차단 권고 — 현실 업무의 예외를 인정하되 감사 기록을 남깁니다"
3. 승인 → 처리 이력 타임라인 확인 (등록→제출→검증→승인 전 과정)

## 3:30 — 월별 보고서

1. 정산보고서 → **월별 보고서 생성** (과제/월 선택)
2. 집계표(비목별 예산·당월·누적·잔액) 즉시 표시 — "이 숫자는 전부 SQL입니다"
3. 서술부에 AI 초안이 채워지는 것 확인(키 있을 때) — "초안임이 명시되고 담당자가 수정 후 확정"
4. 확정 누르면 포함된 집행 건이 잠기는 것 설명

## 4:30 — 대시보드 (관리자 관점 마무리)

- 검토 대기·비목별 예산 소진(80% 경고)·룰 위반 Top 5
- **AI 지표**: 추출 성공률, 제안 채택률 — "AI를 신뢰할 수 있는지도 데이터로 감시합니다"
- 자동화 Before/After — "수기 15분/건은 가정값으로 명시했고, 파이프라인 시간은 실측입니다"

## 예상 질문 대비

- 동시 승인으로 예산 초과? → 예산 행 FOR UPDATE 잠금, 동시성 테스트로 재현·검증
- AI가 금액을 잘못 읽으면? → 판정은 룰이 함 (불일치 FAIL) + confidence 낮으면 수기 대조 플래그
- 외부 API 다운? → 캐시 폴백/미확인 플래그, 워크플로 무중단
- 작업 중복 실행? → idempotency key UNIQUE + 상태 검사 + SKIP LOCKED
