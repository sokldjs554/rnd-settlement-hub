# 검증 룰의 규정 근거

룰 엔진 15종([`backend/app/rules/catalog.py`](../backend/app/rules/catalog.py))이
"그럴듯한 추측"이 아니라 실제 규정에서 나왔음을 보여주는 문서다.
룰마다 근거의 성격이 다르므로 다섯 가지로 구분해 표기한다 — **규정에서 직접 나온 룰과
내부 운영 판단인 룰을 섞어서 주장하지 않는 것**이 이 문서의 원칙이다.

| 근거 유형 | 의미 |
|---|---|
| **[규정]** | 법령·고시 조문이 직접 요구하는 사항 |
| **[세법]** | 세법상 불이익(매입세액 불공제 등)으로 이어지는 사항 |
| **[내부]** | 규정이 아니라 운영 경험칙 — 임계값은 코드 파라미터로 명시하고 조정 가능 |
| **[기술]** | 형식·무결성 검증 (공식 알고리즘 기반) |

## 규정 스택

```
국가연구개발혁신법 (법률)
 └─ 같은 법 시행령  — 제25조 + [별표 2] 연구개발비의 사용 용도(비목 정의)
     └─ 국가연구개발사업 연구개발비 사용 기준 (과학기술정보통신부 고시)
          — 비목별 사용용도·증명자료·정산 절차의 세부 기준
+ 부가가치세법·법인세법 — 증빙(세금계산서)의 세법상 효력
```

## 왜 위반의 비용이 비대칭적으로 큰가

- 연구개발비를 **사용용도·사용기준을 위반하여 사용하는 행위**는 혁신법
  **제31조(국가연구개발사업 관련 부정행위의 금지)**가 정의하는 부정행위다.
- 부정행위에 대해 **제32조(부정행위 등에 대한 제재처분)**는
  ① 10년 이내의 국가연구개발활동 **참여제한**, ② 정부지원 연구개발비의 5배 이내
  **제재부가금**을 병과할 수 있고, ③ 같은 조 제3항에 따라 위반 사용 금액을 **환수**한다.
- 즉 한 건의 잘못된 집행이 "그 돈을 돌려주는 것"으로 끝나지 않는다.
  이것이 제출 **전** 검증 시스템이 필요한 이유다 (README §1 문제 정의).

## 룰별 근거

### 증빙 대사 (R-EVD)

| 룰 | 유형 | 근거 |
|---|---|---|
| R-EVD-001 증빙 미첨부 | [규정] | 사용기준 고시는 연구개발비 지출의 **증명자료 구비·보관**을 요구한다(제72조: 종료 후 5년 보관, 전자문서 가능). 법인세법 제116조(지출증명서류의 수취 및 보관)도 정규 증빙 수취를 요구. 증빙 없는 집행은 정산에서 인정받을 수 없다 |
| R-EVD-002 금액 불일치 | [규정] | 증명자료는 해당 지출을 실제로 증명해야 한다. 장부(입력값)와 증빙 금액이 다르면 그 차액은 증명되지 않은 사용 — 불인정·환수 대상 |
| R-EVD-003 발행일·집행일 불일치 | [규정 보조] | 연구개발기간 내 사용 판정(R-PRD-001)의 기초 데이터 확인. **주의(WARN)에 그치는 이유**: 카드 승인일·계산서 작성일이 실제 거래일과 다른 합법적 경우가 흔하다 — 기계가 위반으로 단정하지 않고 사람이 확인한다 |
| R-EVD-004 사업자번호 불일치 | [규정 보조] | 증빙이 **그 거래처와의 그 거래**를 증명하는지 확인. 다른 업체의 증빙 유용은 전형적 부정 사용 유형 |

### 연구기간 (R-PRD)

| 룰 | 유형 | 근거 |
|---|---|---|
| R-PRD-001 연구기간 외 집행 | [규정] | 사용기준 고시: "연구개발비는 **연구개발기간 종료일 이전에 사용**하여야 한다." 예외: 종료일 이전에 지출원인행위를 한 금액은 사용실적 보고일(시행령 제26조)까지 사용 가능. **시스템은 이 예외를 자동 판정하지 않는다** — 예외 해당 여부는 계약서 등 시스템 밖 정보가 필요하므로, FAIL(차단 권고) + 담당자 override(사유 필수·감사 기록)로 처리한다. override 설계 자체가 이 조문의 예외 구조에서 나왔다 |
| R-PRD-002 종료 30일 이내 | [내부] | 규정 아님. 협약 종료 직전 집행은 정산 시 소명 요구가 잦은 구간이라는 운영 경험칙. 임계값은 `PERIOD_ENDING_SOON_DAYS = 30`으로 코드에 명시 |

### 예산·비목 (R-BGT, R-CAT)

| 룰 | 유형 | 근거 |
|---|---|---|
| R-BGT-001 비목 예산 초과 | [규정] | 연구개발비는 연구개발계획서에 비목별로 계상한 대로 사용한다(시행령 제25조, [별표 2] 연구개발비의 사용 용도). 비목 한도를 넘긴 사용은 계상 기준 위반 — 제31조 부정행위(사용기준 위반)로 이어질 수 있다 |
| R-BGT-002 예산 80% 소진 경고 | [내부] | **80%는 규정이 아니다.** 조기 경보 임계값(`BUDGET_WARN_RATIO = 0.8`)이다. 근거 논리: 비목 예산이 모자라면 **사용계획 변경(일정 기준 이상은 사전승인 대상, 고시 제73조)** 절차가 필요하므로, 소진 전에 조정할 시간을 벌어주는 것이 목적 |
| R-CAT-001 비목 불일치 의심 | [규정 보조] | 비목 분류 기준 자체가 시행령 [별표 2]의 **용도 정의**다(재료비=연구에 직접 사용하는 재료, 활동비=출장·회의·전문가 활용 등). AI는 이 기준으로 제안만 하고(프롬프트에 별표 2 요지 포함), 확정은 담당자가 한다 |

### 거래처 (R-VND, R-DUP)

| 룰 | 유형 | 근거 |
|---|---|---|
| R-VND-001 사업자번호 체크섬 | [기술] | 국세청 공식 검증 알고리즘. 오타를 입력 단계에서 잡아 뒤 단계(상태조회·대사) 오류를 예방 |
| R-VND-002 휴폐업 업체 거래 | [세법] | 폐업자가 발급한 세금계산서는 사실과 다른 세금계산서로 보아 **매입세액 불공제**(부가가치세법 제39조) 위험이 있고, 증빙력 자체가 흔들려 정산 불인정으로 이어질 수 있다. 국세청 사업자등록 상태조회 API로 확인 |
| R-VND-003 상태 미확인 | [내부] | "확인 불가"를 "통과"로 처리하지 않는다는 시스템 원칙. 외부 API 장애 시에도 워크플로는 계속하되 수기 확인 플래그를 남긴다 |
| R-DUP-001 중복 의심 | [규정 보조] | 동일 지출의 이중 청구는 전형적 부정 사용(제31조) 유형. 같은 과제·사업자번호·금액·일자 조합으로 탐지하되, 정당한 반복 거래가 있으므로 주의(WARN)로 사람에게 넘긴다 |

### 기타 (R-DAY, R-AI)

| 룰 | 유형 | 근거 |
|---|---|---|
| R-DAY-001 주말·공휴일 집행 | [내부] | 휴일 집행 자체를 금지하는 조문은 없다. 다만 정산·감사에서 소명 요구가 잦은 패턴이라 미리 표시해 소명을 준비하게 한다. 공휴일 판정은 한국천문연구원 특일 API(없으면 내장 시드) |
| R-AI-001 AI 추출 품질 | [내부] | 규정이 아니라 이 시스템의 신뢰성 요구. AI 미사용·추출 실패·신뢰도 0.7 미만이면 자동 대사를 신뢰하지 않고 수기 대조를 요구한다(임계값 `LOW_CONFIDENCE_THRESHOLD = 0.7`, 근거 데이터는 [AI_EVAL.md](AI_EVAL.md)의 confidence 보정 측정) |

## 조문 인용에 관한 주의

- 법률·시행령 조번호(제25조·제26조·제31조·제32조, 별표 2)는 국가법령정보센터 기준으로 확인했다.
- **사용기준 고시는 개정이 잦아**(연 1~2회) 조번호가 밀릴 수 있다. 본문에 조번호를 적은
  것(제4조·제5조·제72조·제73조)은 2024~2025년 개정판 기준이며, 문언으로 인용한 조항은
  최신 고시 전문에서 해당 문구로 확인하면 된다.
- 실제 과제에 적용할 때는 부처·전문기관별 세부 지침(예: RCMS 매뉴얼)이 추가로 얹힌다 —
  이 시스템의 룰 카탈로그가 순수 함수 목록으로 분리되어 있는 이유다(기관별 룰 추가가
  `ALL_RULES` 등록 한 줄).
